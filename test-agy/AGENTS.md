# Инструкция для ИИ-агента: `test-agy` и гейты патчера

## 1. Что это

`test-agy/` проверяет, что байт-сигнатуры патчера (`source/patcher/agy/patcher.py`,
`CLI_GATE`) находятся во **всех официальных билдах** последнего релиза
`google-antigravity/antigravity-cli` (linux/mac/windows × x64/arm64).
Google периодически перекомпилирует проверку eligibility — тест ловит этот момент.

Файлы:
- `test_cli_releases.py` — сам тест (только stdlib).
- `__init__.py` — пустой, для `unittest discover`.

## 2. Как запускать

```bash
python test-agy/test_cli_releases.py
python -m unittest discover -s test-agy -v
```

Переменные окружения:
- `AGY_RELEASE_TAG` — проверить конкретный тег вместо `latest` (например `1.2.7`).
- `AGY_TEST_CACHE` — каталог кэша архивов (без него каждый прогон качает ~340 МБ).
- `GITHUB_TOKEN` — при rate limit GitHub API.

Скачанные бинари/кэш **не коммитить**. Оригиналы скачанных файлов тест не трогает —
патч проверяется на временных копиях.

## 3. Как устроены гейты

- `Gate(sig, patched, fix, offset, desc)` — `sig`/`patched` это regex по байтам (`re.S`,
  `.` = любой байт, включая `0x0a`). `find()` для agy допускает **несколько**
  вхождений (Go дублирует функции) — патчатся все.
- `MultiGate(...)` — один логический гейт, реализации под архитектуры и билды.
  Один бинарь может совпасть с **несколькими** суб-гейтами сразу (arm64 1.2.7:
  инлайн `w2` в функции экрана + `w4` в хелпере) — патчатся ВСЕ совпавшие,
  иначе экран выживает. Поэтому `MultiGate.resolve_all(data)` возвращает список,
  а одиночного `MultiGate.resolve()` больше нет — не восстанавливать его.
- `fix` обязан быть **той же длины**, что заменяемые байты (размер файла не меняется),
  и использовать **тот же регистр**, что загрузка флага.
- Правила сигнатур: строгий хвост/голова, wildcard (`....`, `[...]`) **только** на
  branch displacement и похожие вариативные байты. Loose-паттерны без хвоста дают
  false positive — так уже было, не возвращать.
- Известные гейты (см. `source/patcher/agy/patcher.py`):
  - `CLI_GATE_X64` — `test rax,rax; je; cmp [rax+8],0; jne; call`, фикс `48 85 c0 90`.
  - `CLI_GATE_ARM64` — старые билды: `cbnz x1; cbz x0; ldrb w1,[x0,#8]; tbnz w1,#0`
    + хвост `bl` + spills (два варианта хвоста через `(?:...|...)`), фикс `21 00 80 52`.
  - `CLI_GATE_ARM64_W2` — CLI 1.2.7+, **главный гейт экрана** (инлайн в функции
    экрана): `cbnz x1; cbz x0; ldrb w2,[x0,#8]; tbnz w2,#0; bl`, фикс `22 00 80 52`.
  - `CLI_GATE_ARM64_W4` — CLI 1.2.7+, проверка внутри хелпера: `cbz x0; ldrb w4,...`
    + `ldp x4,x5,[x0,#0x48]`, фикс `24 00 80 52`.

## 4. Тест упал с `signature not found` — что делать

Это значит, что вышла сборка с новой формой проверки. Алгоритм поиска нового гейта
(так был найден `w4` для 1.2.7, рабочий рецепт):

1. Скачай проблемный бинарь из релиза, распакуй (`antigravity` / `antigravity.exe`).
2. Возьми **x64-билд той же версии** как якорь: форма `test/je/cmp/jne` стабильнее,
   `CLI_GATE_X64` обычно всё ещё матчится. От `call failure_builder` дойди до строк
   ошибок (якорная строка: `Unable to verify account eligibility.`).
3. Найди эту строку в arm64-бинаре (`bytes.find`), затем найди код, который на неё
   ссылается: просканируй исполняемый сегмент на `adrp`, вычисляя
   `target_page = (pc & ~0xFFF) + sext(imm21) << 12`, и отбери те, у которых страница
   совпадает со страницей строки **и** следующий `add` даёт точное смещение строки.
4. Смотри ветвление-охранник перед этим кодом (`cbz`/`ldrb`/`tbnz`/`tbz`) — это и есть
   гейт. Сними точные raw-байты.
5. Собери строгую сигнатуру (см. раздел 3), проверь: **ровно 1 вхождение** в каждом
   бинаре той же платформы (linux/mac/windows arm64), 0 в `patched`-форме, нет
   совпадений в чужих архитектурах.
6. Добавь новый `Gate` + зарегистрируй в `MultiGate`, обнови раздел про CLI-гейт
   в `README.md`, прогони `test-agy` по **всем 6 билдам** с `AGY_TEST_CACHE`.

## 5. Ловушки (проверено на практике)

- В ELF `e_phoff` лежит по смещению `0x20`, не `0x28`. Исполняемый сегмент ищи по
  `p_type == PT_LOAD` + флаг `PF_X`.
- Capstone для `adrp` печатает **абсолютную страницу назначения** (относительно
  переданного базового адреса), а не смещение. Сверяй ручным декодингом по маске
  `(w & 0x9F000000) == 0x90000000`, если адрес выглядит невозможным.
- Бинари PIE (`e_type == 3`): для xref через `adrp` это не мешает — bias сокращается,
  считай всё в домене fileoff: `file_target = (pc & ~0xFFF) + offset`.
- `tbz` vs `tbnz` — разная полярность! `tbz` пропускает `bl` при **сброшенном** бите.
  Не путай с гейтом: в 1.2.7 найдено 167 посторонних `ldrb; tbz; bl` — настоящий гейт
  один, его выдают строки ошибок из шага 3.
- Не считай hex в уме — только кодом. Проверено: ошибки неизбежны.
- Для анализа можно ставить `capstone` через pip локально — это инструмент
  исследования, **не** зависимость проекта (проект и тест — только stdlib).
- Комментарии в коде — на русском (конвенция репозитория).
